## Part I

### Normal Mapping
Normal mapping is a performant technique that allows us to add fine detail to objects without extra geometery. It works by using a normal map texture to pertube the normals across an objects surface, this is passed on through the rest of the lighting calculation to display as if there was actual changes in the geometery.

The original lighting system operated in the world space, however normal maps describe the surface in tangent space. Therefore, to implement normal mapping we first needed to construct the TBN (tangent, bitangent, normal) matrix to transform the normals from tangent space to world space. To do this we utilise the fact that the tangents are already provided for us and can be extracted from the models in `ModelLoader` like we already do for normals. I then followed the way normal data was passed through to all the way to the shaders and did the same for the tangents, modifying the `EntityRenderer` and `BaseLitEntityShader` files accordingly.

Because I modified the Entity Renderers to include a normal map slot, I also needed to create a default normal map texture. For this I copied the implementation of the `default_white_texture` and intialising it to `rbg(128, 128, 255)` in `TextureLoader.cpp`. I then made sure to include this everywhere that the Entity Renderers were called.

Finally I began work on the actual shader implementation for regular and animated entities. For the vertex shader, I used the Gram-Schmidt process to construct the TBN matrix from just the normal and tangent vector, making sure to do it after bone transformation in the animated entity shader. This is then passed to the fragment shader where we sample the normal map, then multiply it by the TBN matrix to transform the perturbed normals into world space. 

Passing the modified `ws_normal` vector into the original lighting calculation results in the lighting effect coming out as intended.

The main issues I ran into with this was a roadblock at the start with getting the tangents, however I figured it out once I started looking at the ModelLoader code. I also spent some time struggling with the compilation before I realised I had not updated the calls to Entity Renderer not including the new default normal map. Finally I spent some time debugging a weird lighting issue on the normal maps, which turned out to be the result of importing them in sRGB format which was easily fixed.

For this feature I was primarily guided by the tutorial on https://learnopengl.com/Advanced-Lighting/Normal-Mapping. This really helped me get my head around the TBN transformations. The part at the bottom about working with complex objects is what got me started modifying the `ModelLoader`.

### Parallax Mapping
Parallax mapping builds on normal mapping to create the illusion of surface depth without additional geometry. While normal mapping perturbs surface normals to fake lighting detail, parallax mapping displaces texture coordinates based on the view direction and a depth map, producing a convincing 3D depth effect that is particularly noticeable at grazing angles.

Since the TBN matrix and tangent pipeline were already in place from the normal mapping implementation, the main work was adding a depth map slot to the rendering pipeline. I added the `depth_map_texture` parameter to `BaseLitEntityRenderData`, bound it to texture unit 3 in `EntityRenderer` and `AnimatedEntityRenderer`, and added a `depth` uniform to `BaseLitEntityMaterial` (defaulting to `0.0f`). Entities without a depth map fall back to the existing `default_black_texture`, which gives a depth value of zero and effectively disables the effect. On the editor side, I added a "Depth Map" texture selector and a "Depth" slider (0.0–0.1) to both `EntityElement.cpp` and `AnimatedEntityElement.cpp`.

For the shader, I implemented steep parallax mapping following the LearnOpenGL tutorial. The fragment shader transforms the view direction to tangent space via `transpose(TBN)`, then the `ParallaxMapping` function steps through depth layers to find the displaced texture coordinate. The total offset is `P = viewDir.xy * -depth` (negated since we use a depth map where white is raised). The layer count adapts dynamically from `minLayers = 8.0` to `maxLayers = 80.0` based on the viewing angle via `dot(vec3(0,0,1), viewDir)`, giving higher quality at grazing angles while staying cheap when looking straight on. A while-loop steps through layers until the sampled depth exceeds the current layer depth, at which point the surface intersection has been found. The resulting `parallax_uv` replaces `scaled_uv` for all texture lookups, and fragments outside `[0, uv_scale]` are discarded to prevent edge artifacts.

Initially I had planned to stick with the most basic implementation, but the initial results were very dissapointing and easily broke down. This led to me looking deeper into steep parallax mapping from the tutorial, which wasn't much more work to implement once I had the basic function, so I upgraded my shaders to utilise it. Another concern about this feature is the heavy impact it has on performance, whilst the view angle optimisation helps a lot, at grazing angles the performance is more than halved.

For this feature I was guided by https://learnopengl.com/Advanced-Lighting/Parallax-Mapping, particularly the sections on steep parallax mapping and dynamic layer count adjustment.
