## Part I
### Shadow Casting
For our first additional feature we decided to implement a shadow casting feature specifically for the directional lights. This turned out to be more complex than anticipated, and involved significantly modifying our rendering pipeline.

I followed the tutorial on https://learnopengl.com/Advanced-Lighting/Shadows/Shadow-Mapping to implement the feature, however some parts were quite different as the project program uses a more complex rendering system involving multiple renderers and shaders. To avoid ruining the engine's modular design,we created a specialized rendering class to handle the shadow logic. Here is a breakdown of the implementation process:

**1. Creating a Specialized Shadow Renderer**
Instead of congesting our primary `MasterRenderer` or `EntityRenderer` with shadow logic, we created a dedicated `ShadowRenderer` class. This encapsulated all the OpenGL state required for shadow mapping, including the creation of a custom Framebuffer Object (FBO) and a high-resolution (2048x2048) depth texture. The class also manages its own minimalist `ShadowShader`, utilizing a simple vertex and fragment shader strictly designed to record depth information.

**2. The Two-Pass Rendering Pipeline**
We modified the `MasterRenderer` to orchestrate two distinct rendering passes each frame:
*   **The Pre-Pass (Shadow Pass):** Before drawing the scene normally, the `ShadowRenderer` calculates an orthographic projection matrix from the perspective of the directional light (`light_space_matrix`). It binds the shadow FBO, adjusts the viewport, and iterates through the `MasterRenderScene`, rendering all entities using the `ShadowShader` to populate the depth texture.
*   **The Main Pass:** The `MasterRenderer` restores the default framebuffer and viewport, but binds our newly generated depth texture to `GL_TEXTURE2`. The standard renderers (`EntityRenderer`, `AnimatedEntityRenderer`) then execute their draw calls as usual.

**3. Uniform Buffer Object (UBO) Integration**
One of the unique challenges of our engine was passing the `light_space_matrix` to the GPU. Because our lighting data is managed via Uniform Buffer Objects (UBOs), we had to update the `DirectionalLight::Data` C++ struct and ensure strict adherence to `std140` memory alignment rules by padding the matrix with `alignas(16)`. The `BaseLitEntityShader` was then updated to copy this matrix to the GPU alongside the light's direction and color.

**4. Shader Implementation and Filtering**
Finally, we overhauled the core lighting calculation in `lights.glsl`. We injected a `sampler2D shadowMap` uniform into the entity fragment shaders and passed it down into a new `calculate_shadow` function. Inside this function, we transform the fragment's world-space position into light-space using the `light_space_matrix` and perform a perspective divide. To improve visual quality, we implemented a dynamic depth bias to eliminate "shadow acne" (self-shadowing artifacts) and utilized Percentage-Closer Filtering (PCF) to sample surrounding texels, resulting in softer, more realistic shadow edges.
